| Claim | Verdict | Sources |
|---|---|---|
| [Spxg](https://github.com/Spxg/sqlite-wasm-rs/pull/219#issuecomment-6733399901): Rust built without `+atomics` can still share linear memory across workers | **True in general, false for memvfs.** A `no_std` module with no atomics links into shared memory once `--extra-features=atomics,bulk-memory` supplies the feature, while one using `std` is refused by std's `-shared-mem` mark. memvfs is refused at every LTO mode, also when C objects or `--extra-features` supply `atomics`, because its own lowered `AtomicPtr` marks it `-shared-mem`. Past `--no-check-features`, safe `AtomicU32` loses updates and `std::sync::Mutex` panics across workers | [LLVM marks `-shared-mem`](https://github.com/llvm/llvm-project/blob/7dba4879803821b376cf32ea7b96406188c70944/llvm/lib/Target/WebAssembly/WebAssemblyCoalesceFeaturesAndStripAtomics.cpp#L155-L163), [`wasm-ld` refuses](https://github.com/llvm/llvm-project/blob/7dba4879803821b376cf32ea7b96406188c70944/lld/wasm/Writer.cpp#L666-L670), [`MEM_VFS`](https://docs.rs/crate/rsqlite-vfs/0.2.0/source/src/memvfs.rs#35), [`no_threads` `Mutex`](https://github.com/rust-lang/rust/blob/fd4400dce238d263ff4239ac9eb902cb9547daf2/library/std/src/sys/sync/mutex/no_threads.rs#L12-L18) |
| #219 as first written: `cfg(not(target_feature = "atomics"))` means single-threaded | **False on stable, beta and 1.82, true on nightly.** Off nightly, `cfg` hides `atomics` on `wasm32-wasip1-threads` and under `+atomics`, and a `+atomics` LTO build links into shared memory where `std::sync::Mutex` panics across workers | [unstable features stay out of `cfg`](https://github.com/rust-lang/rust/blob/fd4400dce238d263ff4239ac9eb902cb9547daf2/compiler/rustc_interface/src/util.rs#L55-L69), [rust-lang/rust#125803](https://github.com/rust-lang/rust/issues/125803) |
| Only a shared memory reaches another worker, and only the runtime can tell on stable | **True** in Node, Chromium, Firefox and WebKit, isolated or not. Posting a non-shared memory throws `DataCloneError`, a shared memory meeting a non-shared import throws `LinkError`, and `wasm_bindgen::memory()`'s buffer is a `SharedArrayBuffer` exactly when the module is shared, without needing that global | [threads proposal](https://github.com/WebAssembly/threads/blob/main/proposals/threads/Overview.md#shared-linear-memory), [posting a shared memory](https://github.com/WebAssembly/threads/blob/main/proposals/threads/Overview.md#example), [memory buffer](https://webassembly.github.io/threads/js-api/#create-a-fixed-length-memory-buffer), [structured serialization](https://html.spec.whatwg.org/multipage/structured-data.html#structuredserializeinternal) |

No experiment rules out a module assembled by hand, linked with `--no-check-features`, or holding no atomics and linked with `--extra-features`. In the first two, safe atomics and `std` locks already race. In all three, the runtime check still sees a `SharedArrayBuffer`.
